dishes categories records members shopping

还剩最后一步，且必须人工操作：把集合权限改成「所有用户可读写」。
微信没有为这一步开放任何接口（见文末的查证），只能在云开发控制台点。

一、怎么设权限（约 2 分钟）

  1. 在微信公众平台点「管理环境」
    左侧菜单「开发与服务 → 云服务」→「云开发」页签 → 环境那一行最右边的蓝色「管理环境」。会打开云开发控制台，可能要再授权一次。
  2. 左侧点「数据库」
    会看到刚建好的 5 个集合（集合管理）。
  3. 点开 dishes，找到「权限」
    一般在集合详情里，或者集合列表右侧的「权限 / 设置」。选 「自定义安全规则」（不是那四个简易权限）。
  4. 把下面这行原样粘进去，保存
    {"read": true, "write": true}
    中文说法就是「所有用户可读写」。
  5. 另外 4 个集合同样操作
    categories、records、members、shopping —— 一共 5 个都要设。
  6. 回小程序，点「重新检查」
    首页那张「云环境还没初始化」的卡片应该消失，然后就能正常用了。

二、为什么必须是这条规则

云开发有四种「简易权限」，但它们没有一种能满足本项目的需要 —— 关键原因是：

在所有简易权限下，小程序端都不能修改「别人创建的」记录。

而家里用这个 App，恰好处处都要改别人的记录：

场景谁创建谁修改简易权限下行不行
买菜的人勾掉已买做饭的人加的采购项买菜的人不行
撤掉别人点的一道菜点菜的人其他人不行
修改菜品信息 / 标常吃录入的人其他人不行
确认这顿饭（会写到当天所有记录）各自创建确认的人不行

所以必须用自定义安全规则 {"read": true, "write": true}。它是恒真规则，还有个好处： 用自定义规则时，系统不会再自动给查询补 _openid 条件，也不会因为「查询条件没覆盖规则」而报 -502003 permission denied。

要特别小心的一点：权限设错不会报错。
如果留在默认的「仅创建者可读写」，App 表面上是好的 —— 你自己录入、自己看得到； 但家人看到的是空的，采购清单也勾不动。不会弹任何错误，只会安静地坏掉。 所以这一步一定要确认设对了。

三、集合被清空时怎么恢复

环境里的集合曾经全部消失过（小程序打开后什么都存不进去，报 -502005 Db or Table not exist）。 现在有脚本可以一条命令重建：

# 本地：需要小程序的 AppSecret（微信公众平台 → 开发管理 → 开发设置）
MP_APPSECRET=xxxx node tools/init-env.mjs

或者在 GitHub 仓库的 Actions 页手动跑 init-env 流程（需要在仓库 Secrets 里配好 MP_APPSECRET）。脚本会自己查出哪些集合缺了、只建缺的那些，建完还会复核一遍。

四、查证结论：哪些能自动化、哪些不能

能力能否自动化依据
新建 / 删除 / 查询集合 ✅ 能 POST api.weixin.qq.com/tcb/databasecollectionadd，凭证 = 小程序 access_token（AppID + AppSecret）
小程序端建集合 ❌ 不能 Database.createCollection() 官方标注「支持端：云函数」
修改集合权限 / 安全规则 ❌ 不能 云开发 HTTP API 的数据库章节只有 13 个接口（databaseadd、databasequery、databasecollectionadd、databasecollectiondelete、databasecollectionget、databasecount、databasedelete、databasemigrateexport、databasemigrateimport、databasemigratequeryinfo、databaseupdate、updateindex …），没有任何权限接口。
实测：tcb/dbmodifyacl 等 6 个候选路径全部返回 40066 invalid url；唯一存在的 componenttcb/dbmodifyacl 用小程序令牌调用返回 48001 api unauthorized —— 它只对第三方平台开放。

结论：「建集合」可以全自动，「改权限」只能人工在控制台点。这是微信的接口边界，不是工具选择问题。
