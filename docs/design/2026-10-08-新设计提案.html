家庭菜单 · 小程序 · 设计提案 v2

从「点菜购物车」
改成一张全家共同安排的餐桌

现在的小程序能用，但它的隐喻是错的：份数步进、加入清单、确认下单——这是外卖 App 的语言，不是家里的语言。家里真正的痛点是三件事：今晚到底吃什么、谁做谁买、上一顿吃了啥。这份提案把产品重心从"选菜下单"挪到"安排今晚"。

01现状诊断

先说明"不满意"具体来自哪。不是配色问题，是产品隐喻和信息架构的问题——只换皮肤解决不了。

1.1 隐喻错位：把家庭当成了外卖平台

现在的做法它在模仿为什么在家里别扭
菜品行右侧 ＋ / － 调份数电商 SKU家里"份数"几乎不重要。真正要定的是做几个菜、几个人吃，不是"这道菜 3 份"
底部悬浮「今日点单 · 共 N 份 · 点击查看清单」购物车家里没有"结算"。要做的是确认这顿饭，然后各自知道该干嘛
「确认点单」按钮下单 / 支付没有金钱交易，却用了交易的动作词，仪式感用错了地方
「我的 → 上传菜品 / 菜品管理 / 分类管理」商家后台做饭的人（往往是长辈）被放进"后台"，而这恰恰是最重要的使用者

1.2 三个真正的家庭痛点，产品都没接住

① 决策疲劳

"今晚吃什么"是全家每天最难的决策。现在产品只提供列表——把 40 道菜平铺出来让人挑，等于把难题原样还回去。

缺决策辅助

② 分工不可见

点完之后：谁做？谁买菜？几个人在家吃？产品里什么都没有。"家庭"只体现在一个昵称输入框和备注里的名字。

缺成员概念

③ 采购断在最后一米

有食材清单，但只能"复制"出去。买菜的人没有可勾选的清单，也没法加"再买瓶酱油"。

缺采购闭环

1.3 具体到界面上的问题

现状 · 问题
  • 首页零起点太陡：必须先去"我的→上传菜品"录菜，才有东西可点。首次打开是空列表。
  • 两行横滑筛选（分类 + 标签）并列，认知重叠、占掉首屏 1/4。
  • 只有列表视图，菜品图片沦为小缩略图；食物类产品最值钱的是食欲感。
  • 日历只显示"3份"——抽象数字，看不到那天到底吃了什么。
  • emoji 当图标（🍚📖🗂📊🥬🎨）混在界面里，视觉不统一、跨机型渲染不一致。
  • 单一橙色铺满，缺少层级：主按钮、标签、徽标全是同一个橙，重点反而不突出。
  • 没有深色模式——晚上在厨房用得多。
  • 没有大字号——长辈看的字偏小。
  • "我的"页是管理后台：4 个管理入口 + 一段使用说明文本，占了全是低频操作。
提案 · 方向
  • 零起点可用：内置示例菜库一键填充 + "最近常吃"快捷入口，30 秒就能玩。
  • 筛选收敛成一条：状态胶囊（全部/常吃/本周没吃）+ 分类下拉，标签降级为筛选面板。
  • 网格大图为主视图，列表为副视图，一键切换。
  • 日历显示菜品色点，一眼看出那天丰盛/清淡/是否重样。
  • 统一线性图标集（24 个），emoji 只留在情绪位。
  • 分层色：赤陶橙=主操作、暖金=关键时刻/今日、菜叶绿=食材与完成，各司其职。
  • 深色 + 大字号跟随系统，厨房/长辈友好。
  • "家庭"页管人管事；管理操作下沉二级页。

02需求重梳理

分三块：你明确要的（保留/改造）、你没想到但该有的（新增）、以及建议砍掉的。

2.1 一句话定位（重写）

给一家人用的餐桌计划本：
今天吃什么 → 谁在家吃 → 需要买什么 → 吃过什么，四件事在一个地方说清楚。

关键词：少决策、看得见分工、有家的温度。不做外卖、不做社区、不做商城。

2.2 你明确要的 → 保留 / 改造

功能处置改造说明
菜品库（图/食材/标签/价格/分类）保留加"谁最爱吃""做法步骤"两个可选字段；价格改为可选（很多家庭菜不标价）
点菜（今日清单）重构从"购物车"改为"今晚的桌"：以菜品卡墙呈现，份数退居次要，突出"谁点的"
日历 + 一键复用重构日期格显示菜品色点；当天详情升级为"那天的一桌菜"；保留"再做一次"
海报分享保留增加"本周餐桌"模板（一周汇总），更适合发家庭群
食材清单升级为采购清单可勾选、可手动加项、分货架分组、过滤常备、多人协作勾选
饮食统计并入日历从独立页移入"日历"页底部，变成"本月回顾"，少一个孤立页面
批量管理保留下沉到"家庭 → 菜品管理"，入口降级

2.3 你没提到、但建议加的需求

这一节是这次提案的重点——产品体验的差距几乎都在这里。

A · 决策辅助（最高价值）

需求优先级说明与理由
「帮我选一顿」决策器P0按"荤素搭配 / 口味 / 人数"洗牌出一桌菜（默认 2 荤 1 素 1 汤），每条可单独"换一个"。这是一句话就能说清卖点的功能
「最近吃腻了」自动降权P07 天内点过的菜在推荐里降权，避免连着吃重样
「本周没吃」筛选P1一个胶囊就能筛出"最近没做过的菜"，比按分类翻更符合真实心理
搭配建议（缺什么）P1选了 3 道荤菜没有素/汤时，提示"还缺个青菜"并一键补。家里做饭的搭配常识，产品可以代劳

B · 家庭与分工（"家庭"两个字必须落地）

需求优先级说明与理由
家庭成员 + 头像P0基于云开发天然带的 _openid 自动识别成员，无需登录。成员可设头像色 + 昵称
「今晚在家吃」开关P0每人一个开关，决定今晚做多少。比"份数"实用一个量级
谁点的菜P0菜品卡上挂点单人小头像。这一条就把"共享"变成"互动"
口味/忌口标签P1成员可标"少辣 / 不吃香菜 / 忌海鲜"，点菜时自动提示冲突。这是家庭场景高频且真痛的
点菜留言P1"想吃妈妈做的红烧肉"这种一句话，比"＋1"有意义得多，也更有家庭的温度
「想吃」热度P2低成本的轻互动：一道菜多人想吃就浮上来

C · 备菜与采购闭环

需求优先级说明与理由
可勾选采购清单P0从"复制文本"升级为真正能勾的清单；多人勾选实时同步，去菜场的人扫一眼就知道还差什么
手动加项P0点单里没有的东西（葱姜蒜、调料、日用品）也能加进去
常备过滤 + 货架分组P1盐/油/酱油默认折叠；按 蔬菜/肉蛋/调料 分组，对齐逛超市的动线
需要提前处理的标记P2"需解冻""需泡发"，买菜回来就能先处理

D · 内容沉淀（家的味道）

需求优先级说明与理由
做法步骤P1录菜时可选填几步做法。家里做饭的长辈不只是"选菜的人"，更是"有手艺的人"——让手艺留下来
「谁最爱吃」P2一道菜标注"爸爸最爱"，是很便宜的情绪价值
菜品来历P2"外婆的做法"这类一句话注记

E · 基础体验（容易被忽略但影响留存）

需求优先级说明与理由
示例菜库 / 一键填充P0最关键的一条。新用户不该先录 10 道菜才能用。提供"填入 12 道家常菜"一键初始化
深色模式P1跟随系统 + 手动三档。厨房晚上用得多
大字号模式P1一键放大 15%，长辈友好
删除可撤销P1目前删菜品/分类是"确认后立即销毁"，共享场景下误删不可逆
数据备份导出P2你原本的待办，保留
弱网兜底与重试提示P2云开发偶尔超时，现在失败是静默的

2.4 建议砍掉 / 降级的

砍 价格字段的前台展示

家里做菜标价格没有意义，反而让界面像外卖。建议：字段保留（兼容老数据），但前台默认隐藏，改为可选的"成本参考"。

砍 "我的"页的使用说明长文

4 条编号说明占了半屏却没人看。改为首次使用的一次性引导 + 空态内嵌提示。

降级 独立统计页

并入"日历"页底部成为"本月回顾"，减少一个孤立入口。

降级 独立"确认点单"页

改为"今晚"页本身即可完成确认，去掉一次跳转（现为 tab 外独立页）。

04产品设计

4.1 四条设计原则

① 减少决策，而不是增加选项

每多一个入口，就是多一次思考。首页只回答一个问题：今晚吃什么。其余都收进二级页。

② 让分工可见

谁点的、谁在家吃、谁在买菜——这三件事在界面上必须一直看得见。

③ 用"这一桌"而不是"这一单"

文案与视觉都避免交易词：没有"下单/结算/份数优先"，只有"今晚的桌 / 确认 / 再做一次"。

④ 长辈是用户，不是被服务对象

大字可选、点击区 ≥44px、满屏 ≤3 个主要动作。做饭的人要能不费力地用起来。

4.2 新信息架构（4 Tab）

🍚 今晚 ← 首页，回答"今晚吃什么" ├── 日期 + 今晚在家吃的人数（成员头像 + 开关） ├── 未点态：大按钮「让家里点菜」/「帮我选一顿」 + 「最近常吃」快捷横滑 ├── 已点态：今晚的菜（菜品卡墙，挂点单人头像）+「还缺个青菜」搭配建议 ├── 采购清单入口卡（N 项未买） └── 底部：确认这顿饭 / 分享到家庭群 📖 菜库 ← 挑菜的地方 ├── 搜索 + 视图切换（网格 / 列表） ├── 状态胶囊：全部 · ⭐常吃 · 本周没吃 · 分类▾ ├── 网格大图卡（点卡片 → 底部弹层加进今晚） └── 悬浮按钮：＋ 添加菜品 📅 日历 ← 回看与回顾 ├── 月视图（每天显示菜品色点，不是"n份"） ├── 本月概览条（本月 18 顿 · 最爱 番茄炒蛋） ├── 点日期 → 那天的一桌菜 + 「再做一次」 └── 底部「本月回顾」：Top3 最爱 + 分类占比 + 搭配建议 👨‍👩‍👧 家庭 ← 管人管事 ├── 成员卡（头像色 + 昵称 + 口味忌口标签 + 今晚在家吃开关） ├── 采购清单（进行中） ├── 菜品管理 / 分类管理 ├── 数据备份导出 └── 设置（深色 / 大字号 / 关于）

对比现在的 3 Tab（点菜 / 日历 / 我的）：把"我的"这个后台式入口换成"家庭"这个关系式入口；把统计从孤立页并进日历；把"确认点单"从独立页收进首页。

4.3 四条核心流程

场景路径关键改进

5.3 形状 / 阴影 / 图标

圆角

卡片 28rpx · 大图卡 32rpx · 按钮全圆 · 小标签 10rpx · 头像圆形。比现状（统一 20rpx）更柔和，且用圆角区分"层级"。

阴影

用暖色极浅阴影替代 1px 灰线：0 4rpx 14rpx rgba(170,130,100,.08)。减少"表格感"，增加纸张层次。

图标

统一线性描边图标集（24 个，2rpx 描边、圆头）。emoji 只保留在情绪位（⭐收藏、🥬食材区标题）。图标用内联 SVG 保证跨机型一致。

07已定决策与实施

7.1 已确认的决策（2026-10-08 定稿）

议题决定落地要点
Tab 结构✅ 4 Tab今晚 / 菜库 / 日历 / 家庭。"我的"这个后台式入口改为"家庭"这个关系式入口。
「份数」✅ 产品里去掉改用「今晚在家吃几个人」。records.num 字段保留不动，兼容历史数据与 Android 版；界面不再出现份数步进与份数徽标。
配色✅ 方案 A 陶土与木桌打底浅色 = A（陶土橙 #D9714E / 米白 #FAF7F3）。方案 B 的墨绿留给深色模式，见《深色模式设计稿》。
成员体系✅ 最小版用云开发自带 _openid 自动识别成员，昵称与头像色本地可改。不做权限管理、不做成员移除。
决策器触发✅ 只做按钮不做"摇一摇"（易误触发）。摇一摇列入 P2，视真实使用反馈再定。
实施节奏✅ 分两批批一 = 架构 + 视觉 + 决策器；批二 = 成员 / 采购 / 做法。避免一次改太多难以回归。
配套文档：《2026-10-08-配色方向对比.html》（三套配色同屏实测，已选定 A）·《2026-10-08-背景色候选.html》（深色底从 B 原值里四选一，已选定 ② #37776A）·《2026-10-08-深色模式设计稿.html》（定稿：底色 = B 的主色）。

批次内容验收方式
