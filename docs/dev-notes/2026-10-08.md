## 批二 · 采购清单 + 决策器完整版

### 1. 采购清单（打通「买菜的最后一米」）

这是诊断里第三个痛点的闭环：原来只能"复制一段文字"，买菜的人没法勾、没法加。

- 新增 `shopping` 集合，**一条记录 = 一个要买的东西**：
  `date / name / qty / group / staple / done / manual / hidden / byName`
- `utils/shopping.js`（纯逻辑）：按关键词把食材归到 **蔬菜 / 肉蛋 / 水产 / 调味 / 主食 / 其他**，
  并对「盐油酱醋淀粉」这类判为**常备**（默认折叠，不占视线）。
- `db.syncShoppingFromDishes(date, derivedNames)` 是核心同步：
  - 清单里缺的派生项 → 新建
  - 已不在今晚菜单里、且未买、且非手动的派生项 → 删掉（不用买了）
  - **手动加的项一律不动**
- **关键设计：派生项不真删，只置 `hidden`**。否则下次打开页面同步时它又会被从菜里推出来。
- 页面 `pages/shopping`：进度条（已买 N/M）+ 谁在买 + 按货架分组 + 勾选（实时同步给家人）
  + 长按删项 + 「＋ 添加要买的」（名称/数量）+ 清空已买 + 一键复制还没买的。
- 今晚页的入口从"食材清单弹层"改成**跳转采购清单页**（弹层那套删掉了）。

### 2. 决策器完整版

批一只有"一键洗牌"，现在补上参数与单条替换：

- 三个参数：**搭配**（2荤1素1汤 / 2荤2素 / 1荤1素1汤 / 随便配）· **人数**（1-2 / 3-4 / 5+ 人，决定做几道）
  · **口味**（随便 / 清淡 / 下饭 / 重口）
- 挑选逻辑 `pickCandidate()`：先按口味关键词收窄 → 再让**久没做过的排前面** → 最后在靠前的候选里随机
  （不是纯随机，避免推出家里根本不吃的菜）
- 每条结果可单独「换一个」，**只在同类（硬菜/素菜/汤）里换**，不动其它三条
- 「全部重摇」重新按参数凑一桌；「就这些，定了」在替换已有菜单前二次确认
