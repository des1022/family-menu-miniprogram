# 开发笔记 2026-10-12

## 日历区块改成「格子块月历」（方案 B，用户选定）

**原来的问题**：月份、星期、日期、图例四样**全部直接铺在页面底色上**，没有任何容器，
所以日期那一片不像「一个东西」，只是字飘着；下面「接下来的安排」是白卡，一对比更明显。

**改法**：
1. 四样东西收进一张卡片 `.cal-card`（`--surf` + `--line` 描边 + `--sh` + `--r-card` 圆角），
   和「接下来的安排」同一套卡片语言。图例移到卡片底部，用一条 `--line` 细线隔开。
2. 月份切换从「居中一行 + 两侧 40rpx 间距」改成 `space-between`，箭头按钮从
   `--surf` 白底描边改成 `--surf2` 浅底（在白卡里再放白按钮会没有边界感），尺寸 64→56rpx。
3. **每个日期＝一枚浅底方块 `.tile`**（96rpx 高、16rpx 圆角、`--surf2` 底）。
   有记录的格子 → `--acc-l` 底 + `--acc-ink` 字（一眼看出这天排过菜）；
   今天 → `--pri` 实心 + 反白字。原来「今天」是画在整格上的色块，现在方块自己承担这个角色，
   所以 `.cell` 的圆角/底色都搬进了 `.tile`（旧的 `.cell--today` 规则整组删掉）。
4. 圆点只在有记录时渲染（`wx:if="{{cell.dots.length}}"`），空日子只显示数字、居中。

**深色模式**：全部走现有变量，只有两处要手工兜 —— 深色下 `--pri` 是白色，
所以「今天」的字要走 `#2A5F54`；「今天」格里的圆点白描边在白底上看不见，深色下关掉。

**教训**：`.cell` 以前同时管「布局 14.28%」和「今天长什么样」，职责混在一起。
拆成 `.cell`（布局）+ `.tile`（长相）之后，改视觉不用碰布局，这是这次能一次改干净的原因。

设计稿：`docs/design/2026-10-12-日历区块方案.html`（四帧对比）、
`docs/design/2026-10-12-日历改后预览.html`（改后浅色/深色）。

### 自查脚本（值得复用）

「模板里的 class 是不是都有样式定义」：
1. 先 `re.sub(r'\{\{.*?\}\}', ' ', s, flags=re.S)` 挖掉所有插值（**关键**，
   否则三元表达式里的 `'chip--on'` 会被当成类名，噪声极大）；
2. 再挖注释，提 `class="..."`，只保留 `[A-Za-z][\w-]*` 的 token；
3. 和「页面 wxss ∪ app.wxss」对比（组件要单独和自己的 wxss 比，因为样式隔离）。
4. 动态类名（`rk-n--{{n}}`）会剩下 `rk-n--`，属正常，人工忽略。

## 菜品管理页缩略图不显示（提交 `3c526dc`）

**原因**：`admin.wxml` 的 `<image class="manage-img" src="{{item.image}}">` **直接绑了原始 fileID**。
本环境存储桶是私有的（「仅创建者及管理员可读写」），fileID 直连读不到 → 显示成一块灰底。
菜库 / 今晚 / 日历 / 编辑页早就改成「云函数换临时链接 + `imgSrc`」了，**只有管理页漏了**。

**为什么会漏掉它**（这条最值得记）：
上次找漏用的关键词是 `grep -rn "dish-dim" --include=*.wxml pages/`。
而管理页这张 `<image>` **没有 `dish-dim` 类**（它是管理列表里的小缩略图，
不走菜品照片那套「深色降亮度」的样式），所以完全扫不出来。

**更可靠的扫法（以后一律用这个）**：
```
grep -rn 'src="{{[^}]*\.image' --include=*.wxml pages components
```
直接找「模板里绑了原始 `image` 字段的 `<image>`」，**和类名无关**。现在全站 0 处。

**改法**：
1. `loadDishes` 里 `await attachImgUrls(decorated)`，再 `setData`（先换链接再渲染，不闪）；
2. 模板改 `src="{{item.imgSrc}}"`，加 `wx:if="{{item.imgSrc && !item.imgFailed}}"`；
3. 加 `binderror="onImgError"` 退回 `--surf2` 灰底占位（原来失败是一块白）；
4. 外层 `wx:for` 加 `wx:for-index="gIdx"`，缩略图带 `data-g` / `data-i` 好定位到
   `groups[g].dishes[i].imgFailed`。

**顺带修 lint**：`tools/lint.py` 的「wx:for 循环变量名可疑」规则只把 `wx:for-item`
收进 known，没管 `wx:for-index` —— 用自定义下标名会被误报。已补 `FOR_INDEX_RE`。
（这条规则本身很值：2026-10-08 日历日期不显示就是它抓出来的。）

## 日历「本月回顾」的月概览 → 暖色横幅（提交 `60b738c`）

**范围**：用户反复强调「其余的保持原来的不变」，所以**只改了 `.calstat` 这一条**，
下面「最常吃的三道 / 分类占比 / 小建议」一个字没动。

**改法**（数值取自设计稿，1rpx = 0.5px）：
| 项 | 原来 | 现在 |
|---|---|---|
| 底 | `--pri-l` 浅橙 + `--pri` 描边 | `--btn-bg`（暖橙渐变）+ `--btn-ink` 白字 |
| padding | 22/26rpx | 28/30rpx |
| 数字 | 44rpx | **64rpx** + `letter-spacing:-2rpx` |
| 右侧 | 「· 最爱 XXX（5 次）」挤在同一行句子末尾 | 「最爱」小标签（21rpx）+ 菜名与次数（28rpx，`display:block`） |

**省事的地方：直接用 `--btn-bg` / `--btn-ink`（主按钮那套）。**
浅色下是暖橙渐变 + 白字，深色下自动变白底 + 深墨绿字 —— **不用写深色覆盖**。
只有投影要手工兜：深色下 `--btn-bg` 是白底，橙色投影（`rgba(196,85,58,.22)`）压在白卡上会脏，
所以 `.theme-dark .statbar` 换回 `var(--sh)`。

**两个边界情况都处理了**：
- 菜名可能很长（「青椒土豆丝炒肉」）→ `.statbar-fav` 限宽 `300rpx` + `text-overflow: ellipsis`，
  否则 `flex:0 0 auto` 的右块会把左边的数字挤扁；
- 没有重复吃过的菜时 `topName` 为空 → 右侧整块 `wx:if` 不渲染（保留原逻辑），
  不会出现「最爱  ·  次」这种空壳。

预览稿：`docs/design/2026-10-12-日历回顾横幅-实现后预览.html`
（浅色 / 深色 / 长菜名与无最爱 三帧，数值全部照抄改后的 `calendar.wxss`）。

## 回顾区三张卡「连在一起」（提交见 git log）

**用户反馈**：贴了设计稿和真机两张图 ——「设计图上有空间好看，软件上连在一起不好看」。

**根因（值得记住）**：`.card`（app.wxss）**本身没有外边距**，我在 `calendar.wxml` 里连着写了三张卡
（最常吃 / 分类占比 / 小建议），它们就**上下贴死**，只有圆角处露出一点背景 → 看着像一整块白。
而设计稿里那 13px 的空隙是我在预览 HTML 的**元素上手写**的（`style="margin-top:13px"` /
`margin-bottom:13px`），**线上并没有对应样式**。

**教训（通用）**：做设计稿时，凡是「真机上不存在的样式」都不能随手写 inline —— 要么它本来就是线上
已有的视觉（照抄数值），要么就得**同时把这条样式落进真实代码**。否则稿子会系统性骗人：
看着更好看，一上线就露馅。这次就是「间距只存在于稿子里」。

**改法**：
1. `pages/calendar/calendar.wxml`：后两张卡加 `card-gap` 类
2. `pages/calendar/calendar.wxss`：`.card-gap { margin-top: 26rpx; }`（= 设计稿的 13px）
3. **顺手把设计稿里那些 inline 间距全部规范化**成 `.gap` 类（三份稿子），
   并写了脚本复查「所有设计稿里还有没有 inline 17/13px 间距」——现在只剩
   `2026-10-12-日历页整体重设计.html`（早期 A/B/C 对比稿）还有 5 处，那份是历史记录，留着。

对比稿：`docs/design/2026-10-12-回顾卡间距-对比.html`（左＝现状贴在一起 / 右＝补上 26rpx，
数据用用户真机那一份）。
