### 2. 分类管理加「编辑」（改名）

用户只要求加个按钮，但「改名」不是改一条记录那么简单：**菜品的分类是存字符串的**
（`dishes.category = '热菜'`），只改分类表的话，名下的菜会全部变成孤儿。

所以改名 = `db.updateCategory(id, {name})` + `db.moveDishesCategory(old, new)`。
交互上没有弹窗：点行内「编辑」→ 名字回填到顶部输入框、按钮从「添加」变「保存」、
下面多一条橙色提示（带取消）。**复用已有输入框比新做一个输入弹窗省事得多**，
我们那个 `ui-dialog` 是纯确认框、不带输入，硬加输入框反而是更大改动。

细节：`focus="{{editingFocus}}"` 只在「点编辑」那一下置 true，
`bindblur` 里立刻复位成 false —— 否则第二次点编辑不会重新聚焦。

顺手把 `.cat-item` 里写死的 `#F5F6F7` 换成 `var(--line)`（深色模式下这行本来是错的）。

### 3. 菜品图片显示空白（别人账号传的图，自己看不到）

**先查官方文档，别猜**：`<image>` 从基础库 2.3.0 起支持云文件 ID，
但官方明确写了「fileID 的直接访问**遵循对象存储的权限配置**」。
云存储基础权限默认是「所有用户可读，仅创建者可读写」，但**单个文件也可以有自己的权限**。

做不了远程查询（没有 AppSecret，拿不到 access_token），所以按「最可能 + 一定更差不了」
的顺序改了三处：

1. **上传时按文件头判真实类型给扩展名**。原来 `cloudPath` 一律写死 `.jpg`，
   但压缩后未必真是 jpg（原图 png 时 `wx.compressImage` / 画布都可能原样返回 png），
   扩展名和内容不符 → CDN 回的 Content-Type 对不上 → 图有可能加载不出来。
   新增 `extOf()`：不传 encoding 调 `readFileSync` 拿 ArrayBuffer，看前几个字节。
2. **加载失败先换临时链接重试一次**：`wx.cloud.getTempFileURL(fileID)`。
   有些权限配置下 fileID 直连读不到、临时链接还能拿到。成功就把 `imgSrc` 换成临时链接。
3. **再失败才退回首字色块占位**。原来失败就是一块纯白，看不出是坏了还是没图。
   `binderror` 只触发一次（`imgRetried` 标记位），不会死循环。

实现上把「喂给 `<image>` 的地址」独立成 `imgSrc`（初始 = `image`），
`image` 保留原始 fileID 用于重试和「有没有图」的判断。

**如果还是白** → 才是真的文件读不到，需要去云开发控制台 → 存储 → 权限设置，
把权限改成「所有用户可读，仅创建者可读写」（改了等 1-3 分钟 CDN 生效）。
