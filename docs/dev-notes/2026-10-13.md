# 开发笔记 2026-10-13

## 菜库：筛选胶囊带数量（美化方案第 ⑤ 条）

用户从昨天的美化方案里挑了第 ⑤ 条（其余没选）。

- `★ 常吃` / `本周没吃` 两个胶囊后面带上数量。
- **数量的口径是「点下去会出现几道」**：把判断抽成 `matchDish(d, kw, key, freq, recent)`，
  列表和胶囊用它同一套逻辑算。点胶囊会清掉左边的分类（`onSwitchFilter` 里 `activeCat` 置空），
  所以胶囊只叠关键词、不叠分类 —— 这样数字和点完看到的完全一致。
  要是按「分类内」算，选着素菜时「★ 常吃 4」点下去只出 2 张，用户会以为坏了。
- 顺带删掉 `buildChips()`（静态构建那两枚胶囊），数量交给 `filterList()` 一起算。
- 样式：`.chip-n { font-size: 21rpx; font-weight: 700; opacity: .72 }`，比主词弱一档。

新增打桩测试 `t-dishes.js`（12 条）：四道菜构造「收藏 / 近一月做过 / 近 7 天做过」的组合，
验证胶囊数字、点下去的道数与数字一致、关键词会一起收窄、左侧分类口径不变。

### 踩坑：打桩测试里别写死日期
今天重跑 `t-tonight2.js` 挂了 2 条 —— 它把「7 天没做了」和「10月12日 周二」写死了，
而 `daysAgoText` 用的是**真实时钟**，过一天就对不上。
→ 凡是要跟时间有关的断言，期望值都得**现算**（`daysAgo(dateStr)` / `new Date()`），
不能写死。测试挂的时候先看是不是「时间漂移」，别急着改产品代码。
