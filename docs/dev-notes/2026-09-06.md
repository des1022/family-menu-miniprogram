### 编译修复 4 连（同一天新项目踩的坑，均已解决）
1. **KSP2 崩溃**：`ksp.useKSP2=true` 时 Room DAO 带方法体的默认实现（@Transaction + body 的 upsert）→ `unexpected jvm signature V`。
   修复：**关掉 ksp.useKSP2（回退 KSP1）** + 把 upsert 合并逻辑从 DAO 移到 RecordRepository（DAO 只留纯 @Query/@Insert）。
2. `AppDatabase`: fallbackToToDestructiveMigration() 报 Unresolved → 直接去掉（v1 首建无需迁移）。
3. CategoryViewModel.add 里在非协程直接调 suspend countByName → 移到 viewModelScope.launch 内检查。
4. **又踩 JVM setter 冲突**（family-order 就踩过！）：DishEditViewModel/HomeViewModel 里 `var x by mutableStateOf + private set` 与显式 `fun setX()` 同名同签名 → Platform declaration clash。批量改名 updateXxx（setName→updateName 等 8 处）+ HomeScreen `vm::setKeyword`→`vm::updateKeyword`。
   **教训重申：新写 VM 直接写成 updateXxx，别再写 setXxx。**
