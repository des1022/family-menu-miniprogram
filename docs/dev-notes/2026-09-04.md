## 家庭点菜小程序（微信小程序原生 + 云开发）

- 交付路径：`family-order/`（工作区根目录下），共 57 个文件，P0+P1 功能全部实现。
- 技术选型：原生小程序 + 云开发（云数据库 + 云存储），无云函数、无第三方库。
- 集合设计：spec 要求 2 个（dishes、orders），实际新增 2 个辅助集合
  - `categories`：承载分类增删改（否则删除空分类无法持久化）
  - `settings`：存放 `{_id:'admin', password}`，实现换设备同步管理密码
- 关键实现决策：
  - 权限落地为「所有用户可读，仅创建者可读写」——小程序端无登录体系，云端无法识别管理员，
    最接近 spec「仅管理员可写」的可行方案；管理页另加 4 位密码防误触。README 里给出云函数加固路径。
  - tabBar 只放 3 项（点菜/订单/我的），购物车做成常驻悬浮入口（spec 描述其为「底部悬浮」）。
  - 图片压缩：先 `wx.compressImage`（仅在宽 >800px 时传 compressedWidth，避免小图被放大），
    再逐级降质量到 ≤200KB；`wx.createOffscreenCanvas` 作为回退方案。
  - 订单实时同步用云开发 `watch()`，不支持时降级为进页面刷新。
  - `App.onLaunch` 里不用 `getApp()`（不可靠），直接用 `this.globalData`。
- 校验方式：node --check 全量 JS、JSON.parse 全量配置、脚本校验页面/组件路径与 WXML 标签配对，全部通过。

## 用户实测反馈：上传菜品图片必闪退 → 已修复（commit 3170a24，构建 33863880204 success）

- 现象：管理页新增/编辑菜品时，从相册选完图一回来 App 就闪退（任何图片 100% 复现）。
- 根因（ImageStore.decodeSampledFromUri）：
  `BitmapFactory.Options().apply { inJustDecodeBounds = true }` 时 `decodeStream` **恒返回 null**
  （只填 bounds、不产生位图）。原代码 `openInputStream(uri)?.use { decodeStream(...) } ?: return null`
  把「流打开成功与否」误判成「解码返回值」，于是正常图片也恒判失败 → `saveFromUri` 抛
  `IllegalArgumentException("无法读取所选图片")` → `viewModelScope.launch` 协程无捕获 → 闪退。
- 修复：
  1. 改为以「openInputStream 能否打开」判成败，仅在解不出尺寸（bounds.outWidth/Height<=0）时判失败。
  2. DishEditViewModel.onPickImage 加 try/catch，新增 `pickError` 状态，失败转 UI Toast 提示、不再崩。
  3. DishEditScreen 用 LaunchedEffect 监听 pickError 弹 Toast 并 clear。
- 教训：**协程里做 IO/解码必须 try-catch 兜底**，任何未捕获异常都会让 App 直接退出；
  `inJustDecodeBounds` 阶段返回值恒为 null 是正常行为，别拿它做成功判断。
  - 分发：Release v1.0 资产已替换为修复版（先 DELETE assets/{asset_id} 再同名重传，asset_id≠artifact_id，
    需 `GET /releases/{release_id}/assets` 查真实 id），下载链接不变、匿名可下（已验证 md5 一致）。

## 固定 debug 签名（支持覆盖安装升级）

- 问题：CI runner 每次构建自动生成新 debug.keystore → 新旧包签名不同 → 只能先卸载再装（丢数据）。
- 解决：仓库根新增固定 `debug.keystore`（标准 debug 口令 android/android，密钥无敏感风险）；
  `app/build.gradle.kts` 加 `signingConfigs.fixedDebug`（storeFile=rootProject debug.keystore）并用于 debug。
  workflow 加 Ensure 步骤：仓库无 keystore 才生成（现在仓库已有，直接复用）。
- bootstrap 流程：workflow 临时生成并 upload artifact → 下载提交进仓库 → 删除临时 upload 步骤。
- 已验证：bootstrap keystore 与仓库 keystore md5 一致（c62a759c...），后续更新可覆盖安装。
