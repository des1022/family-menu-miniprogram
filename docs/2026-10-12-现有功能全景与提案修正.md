## 三、在"读懂之后"剩下的真问题

### 🔴 1. 忌口 10 个选项，没有任何逻辑使用

- 现状：`TASTE_OPTIONS` 在家庭页以多选形式收集（存 `members.tastes`，分号拼接），
  **但全站没有一处读取它做判断**。而提示语写着「点菜时会用到，比如『不吃香菜』」。
- **好消息**：现在实现比我原来说的简单 —— 因为选项是结构化的，而且决策器**已经有现成的关键词匹配机制**
  （`TASTES[].keys` → 匹配菜名 + tags + desc + category）。照同一套加一张映射表就行：
  `不吃香菜 → ['香菜']`、`忌海鲜 → ['虾','蟹','鱼','贝','蛎','鱿鱼']`、`少辣 → 看 tags 是否含「特辣/中辣」` …
- 两个方案（建议都做，也可以只做第一个）：
  - **A 只提示不拦截（推荐先做）**：点菜/详情里标出「含香菜 · 程蒙不吃」，
    把决定权留给人 —— 家庭场景里"提醒"比"禁止"更合适；
  - **B 决策器过滤**：候选池里排除命中忌口的菜。

### 🟠 2. 「今晚在家吃」的人数没接进决策器

- 现状：`countEatTonight()` 已算好，家庭页和今晚页都在显示「X 人」；
  但决策器的「人数」是另外手选的（1-2 / 3-4 / 5人以上）。
- 问题：同一件事填两遍，且可能互相矛盾（家里标 3 人、决策器选 5 人 → 菜量不对）。
- 方案：决策器**默认选中「按在家人数」**（把 `eatCount` 映射到最近的那一档），
  标题显示「3 人（今天在家的）」，仍允许手改。

### 🟠 3. 今晚页的「缺口建议」菜名是写死的

- 现状：`buildSuggest` 能正确识别「这桌缺个青菜 / 再配个汤更完整」，
  但 `hint` 是硬编码字符串：`'蒜蓉小青菜 · 凉拌黄瓜 · 醋溜土豆丝'`。
- 问题：你菜库里不一定有这三道菜 —— 提示就落空了。而且 `onSugTap` 只是跳到菜库，没带筛选条件。
- 方案：**从你自己的菜库里按同一 role 挑 3 道**（复用 `pickCandidate` 的排序逻辑：久没做的优先），
  点提示时直接跳到菜库并筛到那一类。

### 🟡 4. 「强调色」语义超载（UI）

精确统计（不是印象）：`--acc-l` 有 **15 个使用点**，覆盖 **6 类不同语义** ——

| 语义 | 使用点 |
|---|---|
| 时间与记录 ✅ | `.tile--rec`（有记录的日子）、`.up-clip`（日期胶囊） |
| 建议 | `.rv-tip`、`.sug` |
| 排名 | `.rk-n--1`、`.rk-n--2`、`.dp-rank` |
| 收藏 | `.chip--accstar`、`.cd-fav`、`.rd-star`、`.dt-fav--on` |
| 操作 | `.op-edit`（管理页编辑按钮） |
| **纯装饰** ❌ | `.sec-ic--acc`（编辑页区块图标）、`.dc-ic--acc`（决策器图标）、`.big-btn--ghost .bb-ic` |

**建议**：装饰性那三处改成中性色（`--surf2`），收藏类统一用一个色（和「常吃」同一个），
`--acc` 就收敛成「时间 / 记录 / 排名」一个语义。**颜色一个不用改，画面就会安静一档。**

**绿色 `--ok` 同样核了一遍**：共 **14 个使用点**，其中 8 处是真的「状态」
（已上架 `.manage-status--on`、已排 `.ar-btn--on`、已在今晚 `.cd-add--on / .rd-add--on / .mini--on`、
已买 `.grow--done`、自检通过 `.setup-mark--ok`），
**另有 6 处是当装饰色在用**：食材小签 `.ad-ing-i / .dt-ing-i / .hw-ing-i`（×3）、
编辑页区块图标 `.sec-ic--ok`、决策器「人数」图标 `.dc-ic--ok`、编辑页标签 `.chip-tag`。
→ 这 6 处改成中性色，绿色就只剩「完成 / 状态」一个意思，和红色（危险）、暖橙（操作）三者不再打架。

### 🟡 4.5 确认一处死代码

`components/skeleton`（骨架屏组件）：**除自身目录外全仓零引用**（js / json / wxml / wxss 都搜过），
且它的色值是**冷灰 `#F2F3F5 / #E9EBEF`**，与全站暖灰 `#F4EFE9` 不同源。
要么删掉，要么把色值改成暖灰之后再启用。

### 🟡 5. 价格字段的去留（需要你定）

只在菜品管理页显示，别处都不用。三个方向：
A 在采购清单用它估算「今天大概花多少」/ B 菜库卡片显示 / C 删掉减轻录入负担。
**家庭场景我倾向 A 或 C，但这个该你定。**
