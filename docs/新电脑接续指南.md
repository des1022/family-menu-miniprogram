# 新电脑接续指南（Handoff）

> 目的：在任意一台新电脑上，30 分钟内恢复到"可以继续开发/部署"的完整状态。
> 最后更新：2026-10-08

## 📁 三份材料的分工（都保留，缺一不可）

| 材料 | 位置 | 角色 |
| --- | --- | --- |
| **新电脑启动指令** | 工作区根 `新电脑启动指令.txt`（仓库外，含在本文第八节） | 🔑 一次性"钥匙"：粘贴给新电脑的 AI 即触发接续流程 |
| **本文件（接续指南）** | `docs/新电脑接续指南.md` | 📖 事实与操作手册：仓库清单/环境/凭据/命令/进度快照，**AI 与人共用** |
| **开发日志** | `docs/dev-notes/*.md` | 🗂 历史细节与踩坑记录，追溯"为什么这么做" |

> 关键：启动指令的**【2】步明确要求先读本文件**——指令负责"触发"，本文件负责"提供事实"。
> 只有指令、没有指南，接续方只能看到一堆代码而不知项目背景与凭据来源；只有指南、没有指令，则每次都要人手动敲一堆命令。
> 此外，指南还承载**无法从代码推断**的信息：哪些凭据在仓库外、从哪里获取、安全事件记录、部署方式、产品定位决策。

## 五、常用命令

### 小程序：上传新版本 / 生成预览二维码（推荐走云端）

在 GitHub 仓库 `family-menu-miniprogram` 的 Actions 页手动触发 `deploy-miniprogram`：
- `mode=upload` → 上传新版本（之后到微信后台"版本管理"设为体验版）
- `mode=preview` → 生成预览二维码（artifact 下载 `preview-qr.png`）

本地手动跑（需先准备密钥文件到项目根）：

```bash
export MP_APPID=wx83619ff082bae6bf
export MP_KEY_PATH=/path/to/your.key
npm i miniprogram-ci            # 首次
node scripts/upload.js preview  # 或 upload
```

### Android：出包

推送到 `family-menu-android` 的 `main` 即触发 Actions 云编译，产物取 Release 附件。
